# Тест-кейсы по ролям: сквозные сценарии достижения цели

Документ описывает проверку системы **по целям ролей**, а не по экранам: для каждой
роли — конкретная цель, шаги и ожидаемый результат. Проверять можно вручную в браузере
(`http://localhost:9091`) или автоматически (часть сценариев уже покрыта классами
`demo/src/test/java/com/staffsense/demo/journey/`).

## Как устроен доступ

Меню строит сервер: `api/me/RoleScreens.java`. Клиент рисует только то, что пришло
в `GET /api/v1/me` → `screens`. Поэтому «пункта нет в меню» и «API отвечает 403» —
два разных уровня защиты, и проверять надо оба.

Демо-учётки (пароль у всех — `password`, подсказка есть на странице входа):
`admin@staffsense.com`, `hr@staffsense.com`, `pm@staffsense.com`, `exec@staffsense.com`, `employee@staffsense.com`.
Демо-учётка EXEC в сиде есть — `exec@staffsense.com`.

**Меню:** Мой кабинет · Мой день · Опросы · Записки · Портал · ИИ-скиллы (6 пунктов)

### Цель 1.1 — понять, что от меня требуется сегодня

| 2 | Открыть «Мой день» | Блоки: встречи 1:1, опросы к прохождению, записки в работе, остаток отпуска |

**Негативная проверка:** в меню нет «Риски увольнений»; прямой переход на `#/risk`
показывает «Нет доступа», а `GET /api/v1/risk` возвращает **403**.

## 3. HR

**Меню:** всё из PM + Пульт HR · Табель · Отпуска · Найм · Конструктор опросов ·
Управление порталом · Управление каталогом

| Шаг | Действие | Ожидание |

## 6. Общие инварианты (проверять для каждой роли)

1. **Меню = доступ.** Каждый пункт меню открывается; каждый отсутствующий пункт
   либо закрыт 403, либо доступен всем и не требует пункта. Проверяется тестом
   `RoleMenuConsistencyTest`.
2. **Стартовая страница по роли.** Сотрудник попадает в кабинет, остальные — в обзор.
3. **CSRF.** Любой POST без токена — отказ; токен берётся из `GET /api/v1/csrf`.
4. **Чужое не видно.** Сотрудник не видит чужих записок, PM — чужую команду,
   HR — журнал администратора.
5. **«Нет данных» ≠ ноль.** Отсутствие расчёта, права на отпуск или прогноза
   показывается прочерком с пояснением, а не нулём.
6. **Ошибки человеческим языком.** 409 отдаёт текст правила («нельзя заблокировать
   самого себя»), а не «HTTP 409».

Совпадает с тем, что обещает `RoleScreens`: пункт меню есть → API открыт,
пункта нет → закрыт.

### Важно для автоматизации

Ограничитель входа: **5 попыток, затем восстановление 1 токен в 60 секунд**
(`RateLimitingFilter`). При частых прогонах сценариев вход начинает отвечать
`/login?error=rate_limit`, и все последующие проверки видят 401 — это не дефект
доступа, а защита от подбора пароля.

Как обойти при тестировании: перезапустить приложение (счётчик в памяти) или
выдерживать паузу между входами. В ручном тестировании с одним человеком
и четырьмя ролями лимит не мешает.
